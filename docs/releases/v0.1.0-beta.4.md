# pollyDrop · продолжить, а не начинать заново

- Файлы загружаются частями по 1 МиБ. При обрыве связи сервис повторяет запросы; после паузы или перезагрузки страницы можно выбрать тот же файл и продолжить с подтверждённого места.
- Прогресс и зашифрованные части переживают перезапуск backend. SHA-256 защищает от случайного продолжения другим файлом. Повтор потерянного подтверждения не создаёт дубликат передачи.
- Нативное скачивание поддерживает HTTP Range и If-Range. Частичная выдача не расходует получение; завершённая сессия учитывается один раз. HEAD не расходует лимит.
- Пауза не продлевает исходный срок хранения. По умолчанию 1 час, максимум 2 дня, предел файла 25 МиБ. Удаление после последнего получения или истечения срока — по первому условию.
- Сохранены матовое стекло, светлая палитра, адаптивность и полные RU / EN интерфейсы. Добавлены понятные состояния проверки, паузы и продолжения.

**Границы докачки:** ею управляет браузер; встроенные браузеры мессенджеров могут поддерживать её иначе. Сервер не знает, сохранён ли файл на диск. После полной серверной выдачи последнего получения копия удаляется, и продолжить уже нельзя. Срок, отзыв и лимит всегда имеют приоритет. После перезагрузки отправителю нужно выбрать исходный файл; очистка данных браузера удаляет сохранённый секрет продолжения. Локально не сохраняются содержимое файла и открытый пароль.

**Проверка:** 25 серверных тестов; браузерные сценарии обрыва, перезагрузки и перезапуска, потерянных подтверждений, проверки содержимого и Range. GitHub Actions проверяет Chromium и WebKit с эмуляцией iPhone; физический iPhone внутри Telegram отдельно не проверялся.

**Обновление:** в существующем каталоге установки выполните `git pull --ff-only`, затем `sudo bash deploy/server/update-debian.sh`. Миграция БД добавляет таблицы сессий; существующие передачи, ключ шифрования, сроки и счётчики сохраняются. Инструкция: [установка и обновление](https://github.com/pollybich/pollyDrop/blob/main/deploy/server/README.md). Предыдущие релизы и теги сохранены.

**English · resume instead of restarting**

- Encrypted 1 MiB upload chunks, bounded network retries and continuation after a page or backend restart. Reselect the same file; SHA-256 prevents resuming with different content.
- Idempotent chunk/finalization retries preserve the same transfer links after lost acknowledgements.
- Native HTTP Range/If-Range downloads with persistent sessions. Partial delivery and HEAD do not spend the quota; a completed session counts once.
- Original expiry keeps running during pauses. One-hour default, two-day maximum, 25 MiB file limit. Content is deleted on expiry or the last permitted server delivery, whichever happens first.
- Existing light glass design, responsive layouts and RU / EN remain, with clear pause/recovery states.

Browser download-manager support varies, especially inside messengers. The server cannot confirm saving to disk. Once the last complete server delivery deletes the copy, continuation is impossible. Browser storage holds recovery capabilities and file metadata, never plaintext passwords or file content; clearing it loses recovery.

Update with `git pull --ff-only` and `sudo bash deploy/server/update-debian.sh` from the existing installation directory. The additive database migration preserves existing keys, transfers, deadlines and counters. Earlier releases/tags remain available. See the [deployment guide](https://github.com/pollybich/pollyDrop/blob/main/docs/en/DEPLOYMENT.md).
