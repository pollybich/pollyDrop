# Архитектура беты

Браузер → Nginx → Spring Boot → PostgreSQL (метаданные) + файловое хранилище (шифротекст). В разработке роль proxy выполняет Vite. Один backend держит PostgreSQL advisory lock на выделенном соединении; второй экземпляр не запускается. Реплики и балансировка нескольких backend не поддерживаются. Потеря выделенного соединения снимает готовность backend; для повторного получения блокировки нужен перезапуск.

## Передача и секреты

Создание: `POST /api/transfers`, multipart с JSON-частью `options` и необязательной частью `file`. Пример options: `{"kind":"TEXT","text":"Привет","ttlSeconds":600,"maxDownloads":1}`; для файла kind=FILE. Необязательный `password` — до 128 символов. API принимает TTL 600–172800 секунд и лимит 1–10; интерфейс предлагает фиксированные значения; по умолчанию выбран 1 час (3600 секунд).

Ответ 201: `readToken`, `manageToken`, `transfer`. Для обычного создания токены — 32 случайных байта в base64url (43 символа). В возобновляемом протоколе они выводятся из случайного секрета загрузки через SHA-256 с разделением назначения. База хранит только хеши секретов. Ссылки `/s/{readToken}` и `/manage/{manageToken}` независимы. GET метаданных не открывает содержимое; у защищённой передачи публичное имя скрыто до получения. Сами ссылки — секреты. Nginx не пишет пути запросов в access/error log; клиент не использует внешние шрифты, аналитику или рекламные скрипты. Метаданные и управление возвращаются с `Cache-Control: no-store`.

- `GET /api/health` — готовность и версия.
- `GET /api/transfers/{token}` — публичные условия и состояние.
- `POST /api/transfers/{token}/download` — JSON `{"password":"..."}` либо `{}`; явная выдача бинарного файла или UTF-8 текста.
- `POST /api/transfers/{token}/download-ticket` — проверка пароля и условий, без расходования получения; ответ содержит относительные `url` и `statusUrl`.
- `GET /api/downloads/{secret}` — нативная загрузка с `Accept-Ranges: bytes`, одиночным `Range` и `If-Range`/ETag. Начать нужно за 60 секунд; начатая сессия действует до исходного срока передачи. Пароль не попадает в URL; срок/отзыв/лимит проверяются при выдаче. HEAD сообщает размер и заголовки без резерва и расходования получения.
- `GET /api/downloads/{secret}/status` — READY/SENDING/PARTIAL/SENT/FAILED/EXPIRED. Сессии и непрерывный отправленный префикс сохраняются в PostgreSQL; хранятся хеши секретов, максимум 1024 незавершённые действующие сессии. Неиспользованные сессии очищаются после окна старта, начатые — после срока передачи.
- `GET /api/manage/{token}` — состояние для отправителя.
- `DELETE /api/manage/{token}` — отзыв, 204.

Ошибки: 400 неверные параметры, 401 пароль, 404 неизвестная ссылка, 409 выдача уже идёт, 410 доступ закончился, 413 размер, 429 попытки пароля, 507 квота хранения. API не разрешает CORS: браузер работает с тем же origin.

## Возобновляемая загрузка на сервер

Файловый интерфейс использует `PUT /api/uploads/{secret}` (имя, размер, SHA-256, TTL, лимит и пароль), `GET` для прогресса, `PATCH` с `Upload-Offset` и частями по 1 МиБ, `POST .../complete` для сборки и `DELETE` для отмены. Старый multipart остаётся совместимым, текст использует его как прежде. Предел файла — 25 МиБ.

Браузер сохраняет секрет, имя, размер, отпечаток и подтверждённое смещение в localStorage. Содержимое и открытый пароль туда не записываются. После перезагрузки требуется заново выбрать исходный файл: SHA-256 не позволяет продолжить другим содержимым. Очистка данных браузера лишает его этого секрета. Если все части уже приняты, завершить можно без выбора файла.

Каждая часть шифруется AES-GCM с собственным nonce и сохраняется до подтверждения смещения в БД. Повтор принятой части проверяет её содержимое; повтор завершения возвращает те же ссылки. Перед сборкой проверяется полный SHA-256. Перезапуск backend сохраняет части и прогресс; сброшенные резервы выдач не меняют счётчик. Ошибка сети вызывает ограниченные автоматические повторы, затем позволяет продолжить вручную.

TTL отсчитывается с создания серверной сессии, включая паузы. Части удаляются после сборки или по исходному сроку, с таймером и резервной очисткой раз в секунду. Во время сборки части и итоговый шифротекст временно сосуществуют: квота должна учитывать этот запас. Изменять условия сохранённой загрузки нельзя — для этого создаётся новая.

## Выдача и обрыв

Транзакция блокирует строку передачи (`SELECT … FOR UPDATE`), проверяет срок/лимит/отзыв/пароль и записывает уникальный резерв. Ответ выдаётся вне этой транзакции; целостность AES-GCM проверяется до первого байта. Перед каждым блоком 64 КиБ повторно проверяются срок, отзыв и принадлежность резерва. В отдельной транзакции резерв снимается, счётчик увеличивается только после полной отправки и flush. IOException освобождает резерв без расходования лимита. Идентификатор резерва не позволяет старому потоку завершить новую выдачу.

При частичной выдаче сохраняется непрерывное смещение; получение расходуется один раз после полной выдачи в рамках сессии. Повтор с тем же секретом заменяет только её собственный резерв. Пропуск неподтверждённого префикса или устаревший If-Range приводит к безопасному полному ответу 200 вместо 206. Неподдерживаемый или множественный диапазон возвращает 416 без расходования получения. Повтор разрешён после обнаруженного сервером обрыва. Докачкой управляет менеджер браузера, поддержка зависит от браузера и встроенного webview. Она возможна, пока серверная копия доступна: после полного ответа и удаления последнего получения восстановление невозможно. Успешная серверная отправка не означает сохранение пользователем; принятый получателем фрагмент нельзя отозвать. Текст получается через Blob, файл — нативной загрузкой браузера; сервер проверяет GCM в памяти; каждый файл ограничен 25 МиБ, многопользовательская нагрузка ещё не проверялась.

При запуске единственный backend сбрасывает оставшиеся резервы, удаляет сиротские файлы, очищает недоступное содержимое и восстанавливает таймеры. После успешной последней выдачи или отзыва содержимое удаляется синхронно после фиксации транзакции, до завершения обработки запроса. Для срока ставится отдельный таймер; истечение удаляет содержимое и во время выдачи, а поток останавливается при следующей проверке срока. Резервная очистка раз в секунду повторяет неудавшиеся удаления. Метаданные остаются для экрана управления. Точность таймера зависит от работающего процесса и доступного хранилища; при перезапуске просроченные файлы удаляются перед готовностью API. Журнал содержит тип события и внутренний UUID, без паролей, токенов, имён и содержимого.

## Хранение

Формат файла: байт версии 1 + случайный 12-байтовый nonce + AES-256-GCM шифротекст и тег. UUID включён как AAD. Запись через временный файл с атомарным перемещением. Ошибка транзакции создания удаляет связанный файл. Argon2id: память 64 МиБ, 3 итерации, параллелизм 1, соль 16 байт. Пять неверных паролей на сочетание передачи и адреса прямого подключения блокируют дальнейшие проверки на 15 минут, в памяти процесса.

Ключ хранится отдельно в `.env`. HTTPS на внешнем proxy обязателен для публичного использования. Ротация ключа, антивирус, масштабирование, резервное копирование и автоматическая политика удаления метаданных — дальнейшие задачи, не возможности этого выпуска.

## Выбор языка

`GET /api/locale` возвращает `country` и `language` без IP посетителя. `RU` выбирает `ru`, остальные и неизвестные адреса — `en`. Локальная MMDB DB-IP Lite включена в JAR; её SHA-256 и источник закреплены в `config/geoip-source.json`. API не вызывает внешний GeoIP-сервис. Заголовок X-Real-IP принимается только от локального/приватного ingress, где Caddy очищает недоверенные forwarded-заголовки, а Nginx передаёт нормализованный адрес. Автовыбор нужен только до сохранённого ручного RU / EN. Содержимое передач и имена пользовательских файлов не переводятся.
